# Weekly challenges — 2026-11-03

The user approved two starting weekly rules: three new lessons earn20bonusXP; studying on three different days earns30bonusXP. A new lesson means a first rewarded, graded, successful lesson completion. Repeated lessons, practice, placement and challenge bonuses never advance these counters.

Weeks and distinct challenge study dates use UTC (Monday00:00 through the next Monday exclusive). Daily goals/streaks continue using the saved user time zone. Rewards are assigned to the enrolled language of the new lesson that finishes the challenge. There is no client-supplied score, XP, course, reward or claim operation. Bonus XP contributes to that language's ledger/ranking and the user's daily goal, without incrementing completed-lesson count. Lesson result cards now say Lesson XP and link to the separate challenge progress page.

## Data and behavior
Original Challenge/UserChallenge entities include every documented field. Migration20261103132700_AddWeeklyChallenges adds two tables, lengths, composite user/challenge key, foreign keys, positive bounded target/reward, allowed rules, valid time window and reward-after-completion checks. Existing XP uniqueness (user/sourceType/sourceId) also protects bonus issuance.

WeeklyChallengeCatalog derives stable weekly IDs and uses parameterized insert-on-conflict, so multiple instances can create the same two records safely without overwriting existing settings. WeeklyChallengeWorker creates the current catalog at startup, retries every minute, redacts exception details and honors Challenges:AutomaticWeekly (defaulttrue). Completion also ensures the current catalog inside its transaction. A failure remains visible in logs and rolls back the completion; it is not silently treated as a success. Isolated tests disable only the background initializer and explicitly exercise catalog creation.

GET/api/v1/me/challenges is authenticated, private/no-store, rate-limited and read-only. It projects owned ledger progress for active challenges and stored progress for retired/rewarded records, returns no other learner's identity/progress, and caps current/recent own records at50. Existing eligible weekly activity appears without inventing persisted progress or awarding on navigation. If earlier activity already reached a target, a subsequent new lesson triggers recognition in its completing language.

ChallengeProgression uses the persisted lesson completion timestamp for catalog week, eligibility and bonus time, including processing across Monday midnight. It runs only after first lesson XP is saved, while the caller holds the active user/session-family account lock and outer transaction. It counts immutable first-completion ledger rows within the challenge window (and not the future), caps stored progress, creates one reward ledger entry and one in-app notification, updates timezone-local dailyXP, and commits with the lesson and achievements. An unsuccessful reward write rolls all of this back. Replaying completion returns the saved result without another bonus. Reward XP cannot recursively advance a challenge.

The /challenges page shows original-style cards, progress, rewards, dates, expired/earned states, refresh/error/empty handling and explicit UTC explanation. Account/generation guards drop stale responses. Titles use escaped interpolation. Learning navigation and challenge notifications deep-link here. Achievements and challenges share milestone-collection.scss; existing logo/fonts/colors remain.
