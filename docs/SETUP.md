# Local setup

## Open the tools

1. Docker Desktop: engine running.
2. VS Code: open the LexiGo repository root.
3. Visual Studio: open backend/LexiGo.slnx when debugging C#.

Use the README commands to start services, initialize the database and run both applications. Keep only one API copy listening on 5187. Angular 21 is compatible with the installed Node 22.21.0; compatibility reference: https://angular.dev/reference/versions.

## Development infrastructure

- PostgreSQL at localhost:5433; database lexigo; user lexigo_dev; generated password in ignored .env and local .NET User Secrets.
- Mailpit SMTP at localhost:1025; inbox at http://localhost:8025. No messages go to external email providers in this configuration.
- These ports bind to loopback only. The development database role initializes the schema; production still needs separate migration/runtime roles.
- Persistent PostgreSQL volume: lexigo_lexigo_database. Do not run docker compose down -v unless intentionally deleting local data.
- Local data-protection keys persist under the ignored API .local directory so confirmation links survive a restart. Protecting/persisting production keys remains a release requirement.

## Database changes

Migrations live in backend/LanguageLearning.Infrastructure/Data/Migrations. Run initialization explicitly; ordinary API startup never silently creates or recreates the database.

```powershell
dotnet ef migrations add YourMigrationName --project backend/LanguageLearning.Infrastructure --startup-project backend/LanguageLearning.Api
./scripts/Initialize-Development.ps1
```

`database/schema.sql` is the generated idempotent migration script. Apply it before `database/seed.sql`, which restores missing roles, languages, course records and 24 starter vocabulary items without overwriting existing rows. The separate development lesson installer handles versioned lesson content. There is no built-in admin account.

The [OpenAPI snapshot](openapi.json) is generated by the development API. To refresh it after building the Release API, run `./scripts/Verify-LearnerBrowser.ps1 -Configuration Release -Spec guest-lesson.spec.ts -ExportOpenApi`. The script uses disposable services and writes the snapshot to `docs/openapi.json`.

## Account verification

Visit /register, complete the form, then open the email in Mailpit. Follow its link and press Confirm. Links expire after 30 minutes and succeed once. A resend page is available; emails for the same unconfirmed account are spaced by at least five minutes.

After confirmation, visit /login and sign in. /account lists active devices and supports signing out one or all devices and changing a password using the current password. Password changes sign out every device.

Forgot-password sends a 30-minute reset link to Mailpit. Requesting it does not change the password. A successful reset works once and revokes existing sessions; sign in with the new password afterward.

Access tokens stay in browser memory. Reloading the page restores a session through the protected refresh cookie; no access token is saved in localStorage. Production cookies require HTTPS; local Development uses HTTP on loopback. Signing RSA keys persist in the ignored API .local folder. Production must supply Authentication:SigningPrivateKeyPem through secrets and protect persistent data-protection keys. See ACCOUNT_SECURITY.md.

Visit /account/security to set up an authenticator using its manual time-based setup-key option. Verify the app code, save the ten recovery codes shown once, and sign in again using a new code. Security changes sign out all devices. Password plus a recovery code can sign in when the authenticator is unavailable.

Privileged accounts cannot sign in without two-factor authentication and cannot disable it. Initial enrollment currently happens as Learner before a role is assigned. Privileged provisioning/replacement recovery still needs implementation; never grant a privileged role first and expect a setup bypass. Free/Premium, learning and AI features remain pending.

## Checks and troubleshooting

For real-inbox delivery, follow [Brevo preparation](BREVO_SETUP.md). Mailpit remains active until provider credentials, sender verification and an agreed recipient are ready. Configure-Brevo.ps1 prompts for a hidden SMTP key and deliberately leaves delivery disabled; it has not been run with real credentials.

- Run dotnet test for the PostgreSQL-backed account/session/recovery suite. The fixture explicitly resolves the API content root to support the apostrophe in this workspace name.
- If the terminal sandbox blocks local TCP/Docker, use an appropriately authorized terminal; do not weaken application security or expose services publicly as a workaround.
- If MSBuild parallel workers cannot communicate in the environment, use `dotnet build backend/LexiGo.slnx --disable-build-servers -m:1`.
- If Visual Studio reports address already in use, stop the existing terminal/API process before pressing Play.

## Profile and email-change settings

Account links open /account/profile and /account/email. See PROFILE_SETTINGS.md and EMAIL_CHANGE_SECURITY.md for current persistence, access rules, pending consumers and security checks. Apply AddStudyPreferences through the normal development initialization command. The confirmed email-change flow reuses encrypted Identity token storage and needs no additional schema. External email stays disabled after the approved single Brevo test; do not infer ongoing sending from a generic accepted request.

## Private lesson-audio development storage

Follow [PRIVATE_AUDIO_STORAGE.md](PRIVATE_AUDIO_STORAGE.md). With the database `.env` already prepared, run `./scripts/Initialize-Storage.ps1`, then `docker compose --profile storage up -d --wait storage`. Apply AddMediaLifecycle through the normal migration command, then restart the API after changing User Secrets. Storage is optional until configured, binds only to loopback and has persistent volumes. Do not reset volumes to troubleshoot startup. Staff upload/review at `/manage/media` requires a properly enrolled privileged account; see MEDIA_WORKFLOW.md. A healthy storage container alone does not establish licensed curriculum or learner playback.
